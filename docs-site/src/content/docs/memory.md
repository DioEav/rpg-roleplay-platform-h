记忆系统决定 GM 能「记住」多少历史信息，以及哪些内容会在每一轮对话里被检索并注入到提示词中。记忆分为两个层面：游戏运行时可在侧栏记忆面板查看和编辑当前存档的记忆内容；全局默认行为在「平台设置」→「记忆」调节。

入口：游戏内右侧面板「记忆」标签；或「平台设置」→「记忆」。

---

## 关键概念

### 记忆桶

系统把记忆按性质分成三类桶：

- **固定记忆桶（Pinned）**：手动钉住的事实，优先级最高，每轮按 `pinned_max` 全量候选注入（仍受 token 上限裁剪）。适合放绝对不能被遗忘的设定，例如「主角已经失去了左手」。
- **世界记忆桶（World）**：主线/当前目标、事件事实、玩家笔记、归档摘要。候选窗口按最近 N 条起步，最终注入量由 token 预算决定，不是全量倾倒。
- **角色记忆桶（Character）**：能力与资源等角色持久状态。候选窗口比事实更宽，最终仍由 token 预算裁剪。

三个桶可在「设置 → 记忆」里分别开关；关闭后对应内容不再进入 prompt（MemoryProvider 是唯一注入源）。关闭 world 桶期间会暂停 facts 自动归档，避免“关一段时间再打开，中间事实已经被压成摘要”。「设置 → 记忆」和游戏内「记忆」面板现在都提供召回窗口、token 上限、token 估算系数、固定记忆上限、事实软上限、摘要批量周期和桶开关；游戏内面板按存档覆盖，只保存你改过的字段，其余继续跟随全局设置，每个字段都可以单独「恢复跟随全局」。

### 召回与注入

每轮 GM 生成回复前，系统先取出各桶的候选窗口（事实/摘要按 recall 窗口放大，笔记/能力/资源有更高的候选下限），再由 section 权重和 token 上限决定实际注入量；预算紧张时优先保留最新条目。active 事实超过「事实软上限」时，每回合都会检查并按最旧优先归档到上限；摘要本身按「归档扫描周期」或攒满一块后批量生成，避免每回合产出碎片摘要，同时不留中间断层。token 估算默认仍是字符数 // 2，可用「token 估算系数」对中文 token 密度高的模型调保守；记忆层与「相关往事」层共用同一系数。同时按本回合输入做一次轻量关键词/实体/当前地点召回，补少量不在候选窗口里的旧事实/旧笔记。真正的语义召回由「长局相关往事召回」层负责（`episodic_recall`，默认开启，可在设置里关闭）。

### 事实库（Facts）

GM 每轮叙事结束后，Extractor 会自动从对话中抽取重要事实并写入事实库。事实库内容无需手动维护；注入时取最近 N 条，更早的事实归档后压缩为概要。归档原文仍保留在「远期事实存档」中，开启「长局相关往事召回」后可按相关性找回，默认不参与每轮注入。GM 明确纠正旧事实时会将其标记为「已取代」：旧版本保留在存档历史里但不再注入，不会让两个矛盾版本同时生效。玩家也可以在记忆面板直接编辑、删除或固定事实；「历史记忆」区支持搜索、状态筛选和分页，并可查看已归档/已取代条目、一键恢复。恢复旧版本如果会和当前版本冲突，会先要求确认，确认后把当前相似/直接替代版本标为已取代。归档事实超过 state 上限（1000 条）后，更早的原文写入 KB 冷存储并永久保留（按 save+分支谱系+afactc 前缀下推查询）；`query_memory` 的 archived scope 会自动回退检索。玩家显式删除的事实会立即退役热/冷事件，并记录文本 + hash tombstone，不会被冷存储召回。历史面板的「查更早归档」也走同一服务端分页接口。世界事件同样保留完整历史（kevtc）：状态/世界书只显示最近 100 条，世界书面板可搜索/分页查看更早事件。归档摘要会带紧凑的人物/地点/时间元数据，篇章汇总还会保留心境链。GM 还可以用 `query_memory` 按文本、实体、时间、状态（active/superseded/orphaned/rejected/archived）查询当前/归档/摘要/篇章记忆；`scope=all` 会按文本跨层去重。每 5 个阶段会生成一条确定性的「篇章」汇总（包含玩家关键决策），只汇总最近 4 个 phase 之前的阶段，避免与 phase digest 重复。

### 与世界书的关系

世界书和记忆桶是两套平行机制，互不覆盖：

- **世界书**：存放手动维护的世界设定条目，按关键词或相关性注入。适合放长期稳定的世界规则、人物简介、地名说明。
- **记忆桶**：存放游戏运行中动态产生或手动钉住的事实，侧重当前存档的运行状态。

两者都会在同一轮里各自贡献内容给 GM，共同占用 token 预算。开启大量世界书条目时，建议适当控制记忆注入上限。

## 常见任务

### 钉住一条重要事实（游戏内）

进入游戏 → 右侧面板「记忆」标签 → 在「固定记忆」区域点击 + 按钮 → 输入内容并确认。该条目立即被钉住，下一轮 GM 就会读到它。

### 解除固定记忆（游戏内）

在「固定记忆」列表中找到该条目 → 点击右侧 × → 确认解除。解除后该条目不再保底注入，但内容不会丢失。

### 添加玩家笔记（游戏内）

右侧面板「记忆」标签 → 「玩家笔记」区域点击 + → 输入内容。笔记是私人备忘，GM 不保证每轮都读到（区别于固定记忆的强制注入）。

### 查看本轮 GM 参考了什么

右侧面板「记忆」标签底部有「召回」区域，展示本轮从原文/历史检索到的片段以及段落数。

### 调整记忆参数（设置）

「平台设置」→「记忆」，可以调节召回深度、历史摘要窗口、每轮注入 token 上限、自动归档轮数，以及各桶的开启状态。所有改动自动保存，下次 GM 调用立即生效。

## 常见问题

**固定记忆和玩家笔记有什么区别？**
固定记忆每轮必进 GM 上下文（有 token 配额，勿堆砌过多）；玩家笔记只供参考，GM 不保证每轮都读。

**固定记忆桶满了会怎样？**
固定记忆桶有上限（默认 20 条，可在设置里调整），达到上限后新增会被拒绝；请先删除旧条目。不会自动转入事实库。

**GM 总是忘记某件事，怎么办？**
在游戏内记忆面板把该事实手动钉住，进入固定记忆桶后每轮必然注入。若遗忘仍然发生，检查「每轮注入记忆 token 上限」是否设置得过低，导致内容被截断。

**关闭某个记忆桶会不会丢失里面的内容？**
不会丢失。关闭桶只是停止检索和注入该桶的内容，桶里的数据仍然保留，重新开启后恢复正常。

**记忆和世界书同时开着会不会 token 超标？**
两者都占用同一轮的 token 预算。如果上下文经常被截断，可以降低「每轮注入记忆 token 上限」，酌情关闭某个记忆桶，或减少世界书中常驻注入的条目数量。
